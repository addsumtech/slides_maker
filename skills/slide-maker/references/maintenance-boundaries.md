# Maintenance boundaries — what not to collapse

**Read this before merging, removing, or "simplifying" any gate, artifact, or check in this
skill.** Not before an ordinary deck build; this file is for whoever is changing the skill itself.

`check_skill_lossless.py` already guards one half of a refactor: it proves the *bytes* survived.
It cannot see the other half. Two gates merged into one, a warning promoted to an auto-fix, a plan
field trusted instead of re-tested — every one of those keeps every line of text and still removes
the property the text was describing. The lossless check reports a perfect score while the skill
gets worse.

So the boundaries below are **negative contracts**. Each one names a tempting simplification and
what it would cost. Violating one is not a refactor; it is an architecture change, and it should be
argued for on its own rather than arriving inside a cleanup commit.

Where a boundary is decidable by a program, `tests/test_maintenance_boundaries.py` asserts it. The
rest are here because someone has to read them — which is why this file is short and why every
entry says *why*, not just *don't*.

| Do not | Why |
|---|---|
| **Merge build-time `lint_layout` and render-time `lint_deck`** | They answer questions that cannot be asked at the same moment. `lint_layout` reads the `.pptx` and must fire *before* a render is paid for; `lint_deck` reads the rendered PNGs and can see what no geometry knows — text that renders as nothing, a plate that vanishes into its ground, a deck with no light/dark rhythm. Merging them either delays the cheap checks or invents pixel answers before pixels exist. |
| **Add auto-fix to any lint** | A mechanical patch silently overwrites design intent and ships a worse page than the one it "fixed". The findings are written to be *acted on*, which is why every message names a remedy instead of applying one. This is also why `--fix` has never existed: its absence is the contract. |
| **Trust a plan field as evidence about the built deck** | A field written at plan time, before any slide exists, proves nothing about what got built. Measured repeatedly: an `icon_family: none — <reason>` waiver that was true when written and false by page 3; a declared single-hue palette that shipped two library defaults; a `form_reach` claim beside a deck of raw boxes. Every plan claim that can be re-tested against the `.pptx` is re-tested against the `.pptx` (`_report_icon_waiver`, `_report_palette_drift`, `_report_form_reach`, `_report_carried_by`). A new plan field should arrive with its re-test, not instead of one. |
| **Let a gate's vocabulary drift from what the linter emits** | A gate that names codes nothing produces believes it is enforcing them and can never fire. Measured: two of seven `STRICT_STATS` entries matched no linter output at all, while the test fed the gate its own expected shape and passed. Cross-file agreements are decidable by a program; assert them. |
| **Move operational knowledge out of SKILL.md into `references/`** | Layer 2 is safe only for content with a backstop — a required artifact, a deterministic check, or a checklist item naming the file. Which component to reach for and what to scan a render against have none: nothing reports their absence, the build succeeds, the lint passes, and the output is quietly wrong. Measured on the split that tried it: the next real run read 3 of 10 reference files, hand-rolled a chart with the wrong helper, and shipped zero icons — passing every automated gate. |
| **Widen an exemption to quiet a false positive** | The tempting fix for a check that cries wolf is a broader exemption, which usually silences the true positives with it. The pattern that works: measure which cases misfire, name the *class*, and guard exactly that class — `RAGGED LEFT EDGE` reports nothing on a correct deck because of five specific guards, not one loose threshold. If a check cannot reach acceptable precision, do not ship it; a gate nobody trusts is worse than no gate. |
| **Fan out a single argument across blind agents** | Parallelism speeds *gathering* and never *understanding*. Separate documents, separate asset prep, separate review lenses: fine. One paper's intro / method / results split across agents that cannot see each other: the through-line is one mind's job, and the seams show. |
| **Turn the actor–critic loop into a single pass** | Its *weight* is what scales to stakes — two focused lenses for a quick deck, a full panel for a high-stakes one. Its existence does not. The critic is the only stage that judges the deck as a reader rather than as a file. |
| **Assume an asset that exists is an asset that worked** | A failed generation writes a truncated file or a flat placeholder plate; a bad crop writes a fully transparent frame. All three embed without complaint and pass every geometric and density check, because the picture does occupy its box. `ASSET NOT USABLE` exists because existence is not success. |
| **Wire the round-trip / batching metric into any gate** | `roundtrip_report.py` measures what a build cost in turns, and that number is worth knowing — the deterministic pipeline is 9 seconds against an 88-minute build. But the cheapest way to make it smaller is to LOOK AT LESS: skip a render read, skip a verification, apply a fix without confirming it landed. As a target it is satisfied by exactly the behaviour every other check here exists to prevent. It stays a developer measurement, run after the fact, read by a person. |
| **Let `contact.png` stand in for reading the slides** | The contact sheet exists so deck-level rhythm is visible at all; at 46 px/inch, body text on it is 8.6px and a source line 6.4px. It can answer "which pages deserve attention" and nothing else. A visual self-check performed on the sheet is a self-check performed on titles and colour blocks, reported as if it had covered typography, contrast, overlap and labels. |
| **Route the pipeline through `deck_cycle.py`** | It is a convenience entry point that collapses one iteration into one round-trip; `render_deck.py` and `lint_deck.py` remain the entry points the workflow names, and every step it chains can still be run alone. Making it the only path would mean a stage could be dropped from the loop by editing one file, with nothing else noticing. |
| **Treat a review's quoted measurements as evidence** | They read like evidence and nothing checks them. Measured on one delivered deck: of six critic claims re-measured by hand, THREE were factually wrong — and all three were among the ones quoting precise figures ("the bar is also INK" — it is gold; "the rule spans x=0→1439" — it spans 205→787; "this is the number the ledger failed to verify" — it is confirmed there, and is not on that slide). Two of them nearly became lint checks here, built to enforce a defect that did not exist. An automated re-measurer was written and abandoned: associating a coordinate with the object it describes cannot be done reliably by regex over prose. So the rule is human: re-measure a number before acting on it. The review's *editorial* findings — whether a title states a conclusion, whether a claim overstates its own chart — survived every check and are what it is for. |
| **Let `arc_divergence.py` PICK the arc** | It measures whether the candidates are different stories and whether the losers were ever developed. It has no opinion about which one this room needs — that is a judgement about audience, purpose and what the evidence can actually carry, and a script that ranked arcs would be an aesthetic score wearing a lint's clothes. Same shape as `directions_diversity.py`: it flags a collapse, and a flag is REDIVERGE-or-justify, never a kill. Note the honest limit, which it shares with the direction gate: the verdict rides on a checkpoint line, so it can be *written* without being *run*. Do not "fix" that by having the coordinator auto-generate the line — the fix, if one is wanted, is making the JSON an artifact the checkpoint points at. **And do not close its ROLE vocabulary.** `content-planner.md` calls that list "a vocabulary, not a straitjacket"; the first version of the script raised on anything outside it, which meant a planner following its own brief could be hard-blocked for writing `demo`. A gate that contradicts the agent brief it enforces is a wall. Unrecognised roles are accepted and merely reported, and the cost of that is precisely one thing: two different typos of a role read as divergent instead of identical, weakening one of four axes slightly. `shape` stays closed because it is the loudest axis and its nine entries cover every arc shape the skill documents. |
| **Drop the `complex` and `data` anchors back to one signature page** | One page proved the aesthetic risk and only that. The design approved on the deck's most spacious slide can still fail to hold its densest one, and a palette and type scale resolved entirely against text still meet their first native chart somewhere — both used to surface at Step 5, at full deck size, where the fix is a rebuild. The extra two cost ~0s of machine time and ZERO extra round-trips (same build script, same render call); what they cost is authoring two slides earlier than you wanted to. That is the trade, and it is the good side of it. |
| **Re-inline the material-probe contract into the gates** | Three gates now enforce the Step-2 probe — `render_deck.py --gate-check`, `deck_gates.py`, and (since the Codex arm was added) `codex_delivery_gate.py`. `scripts/material_probe.py` is the single place the CARVE LIST, the waiver rules and the two accepted file keys are written; `tests/test_material_probe.py` asserts by AST that all three import it and that none carries a private copy of the tuple. Inlining it back reads as harmless — it is four words — and is how the anchor proof's file key ended up spelled `path` in one gate and `png` in the other. 🔴 Do not "simplify" by folding the ARTIFACT check in too: the shared path opens the PNG and refuses a flat one, the Codex path binds it to a SHA-256 and to the final PPTX, and one shared implementation would have to be the weaker of the two. |
| **Re-implement the anchor-proof rule inside either gate** | `render_deck.py --gate-check` and `codex_delivery_gate.py` both enforce it and have already diverged once on this exact field — the file key was spelled `path` in one and `png` in the other, so a bridged run wrote what its own gate demanded and the other rejected it for the key name alone. `scripts/anchor_proof.py` is the single place the rule is written; `tests/test_anchor_proof.py` asserts by AST that both still import it. A local copy looks correct in review and simply stops being the same rule six months later. |
| **Grow `evals.json` toward a scenario count** | Scenarios are chosen by BLIND SPOT, not by number. Each of the later three sits on a defect class this repo has actually shipped while every gate passed clean — CJK faces, signed native bars, non-16:9 — and each arrived with an assertion that did not exist before it. A scenario that only re-runs assertions the existing ones already run measures nothing new; twenty of those are not broader coverage, they are a longer bill on a run that builds real decks with real tokens. And do not add an eval whose input artifact does not exist: unreproducible scenarios inflate the count and decide nothing. |
| **Move a check from deterministic code into the critic's judgment** | The direction of travel is one-way: deterministic > required field > checklist > prose. A contrast ratio, a bar-length proportion, a schema order — each has one arithmetic answer, and paying model prices for it in a dispatch that might not look next time is a downgrade even when the model gets it right. The reverse move (critic judgment → deterministic check) is always welcome. |
